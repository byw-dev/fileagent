# SCHEMA.md — 任务字段定义与规范

> 本文件由人工维护，定义任务系统使用的所有字段、状态枚举和文件结构规范。

---

## 文件结构

```
docs/tasks/
├── SCHEMA.md          # 字段定义、状态枚举、优先级说明（本文件，人工维护）
├── backlog.md         # 待规划任务（粗粒度，无需 Agent 读取）
├── active.md          # 当前 sprint 的活跃任务（Agent 的主要输入）
├── bugs/
│   ├── open.md        # 未解决 BUG（结构化，Agent 可直接消费）
│   └── closed.md      # 已关闭 BUG（归档，Agent 不读）
└── changelog.md       # 历史记录（纯人类阅读）
```

> Agent 每次开始任务前，应按以下顺序阅读：
> 1. `CLAUDE.md`（技术栈与编码规范）
> 2. `docs/tasks/active.md`（当前任务）
> 3. `docs/tasks/bugs/open.md`（如果当前任务涉及 Bug 修复）

---

## 状态枚举

| 符号 | 含义 |
|------|------|
| ⬜ | 未开始 |
| 🔄 | 进行中 |
| ✅ | 已完成（验收通过） |
| ❌ | 阻塞中（等待前置依赖或人工决策） |
| ⚠️ | 部分完成（有已知缺陷，见说明） |

---

## 优先级枚举

| 符号 | 含义 |
|------|------|
| 🔴 P0 | 阻塞（必须立即修复；影响主链路）|
| 🟡 P1 | 高优先级（影响功能完整性，不阻塞主流程）|
| 🟢 P2 | 中优先级（质量/体验问题，可在当前 sprint 完成）|
| ⚪ P3 | 低优先级（可延期到下个 sprint）|

---

## Bug 字段定义

| 字段 | 必填 | 说明 |
|------|------|------|
| `ID` | ✅ | 唯一编号，格式 `BUG-XXX` 或沿用任务编号 |
| `标题` | ✅ | 一句话描述问题 |
| `严重程度` | ✅ | P0/P1/P2/P3 |
| `状态` | ✅ | ⬜/🔄/✅ |
| `前置依赖` | — | 其他 Bug 或任务编号 |
| `根因` | ✅ | 精确代码位置 + 根因说明 |
| `修复方案` | ✅ | 受影响文件 + 修改要点 |
| `验收标准` | ✅ | 可验证的通过/失败条件 |

---

## 任务字段定义（active.md）

| 字段 | 必填 | 说明 |
|------|------|------|
| `ID` | ✅ | 任务编号（如 `T3-2`）|
| `标题` | ✅ | 一句话描述任务 |
| `状态` | ✅ | ⬜/🔄/✅ |
| `前置依赖` | — | 编号列表 |
| `涉及模块` | ✅ | controlplane / agent / webui / sdk |
| `验收标准` | ✅ | 可验证的通过/失败条件 |

---

## 命名约定

- Phase 主线任务：`T{phase}-{seq}` 例：`T3-2`
- Phase 2 遗留补完：`T2-X{seq}` 例：`T2-X4`
- Phase 3 前置关卡：`P3-P{seq}` 例：`P3-P1`
- Phase 3 修复组：`T3-{task}-FIX-{letter}` 例：`T3-2-FIX-A`
- Phase 4 任务：`T4-{seq}` 例：`T4-1`
