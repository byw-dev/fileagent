## 背景与约束

采集数据存在多维度变种，当前仅靠 `file_types`（glob 归类）会导致「类型爆炸」。设计据以下约束提炼：

- **维度** = 厂家 / 型号 / 站点 / 传感器类型 / 数据版本 + **加工级别**（`raw → calibrated → derived`，即血缘）。
- **元数据必须在采集规则处声明**（源头即元数据）。
- **SDK 是主要消费方**（按维度拉取 / 订阅）。
- 需要**对账**（应到未到）与**历史回溯打标**。

## 三个模型（round 6）

| 能力 | A 文件标签 (`6a`) | B 数据集 (`6b`) | **C 混合（推荐 `6c`）** |
|------|:---:|:---:|:---:|
| SDK 按标签/维度拉取 | ✓ 拼查询 | ✓ 订阅 | ✓ 两者都有 |
| 对账（应到未到） | ✗ 无载体 | ✓ 一等能力 | ◐ 二阶段补齐 |
| 血缘（raw→calibrated→…） | ✗ 弱 | ✓ 数据集级 | ◐ 二阶段补齐 |
| 历史回溯打标 | ✓ | ◐ 需迁移 | ✓ 一阶段就有 |
| 长尾 / 临时数据成本 | 低 | 高（先建模） | 低 |
| 后端 + UI 改动量 | 小 | 大 | 小 → 中（分期） |

## 推荐方案：混合演进（`6c`），分期交付

**第一阶段 · 现在做 —— 受控标签打底（= 方案 A + 词表治理）**
1. 管理员预定义 tag key 词表：`vendor / model / site / sensor / data_version / level`。
2. 采集规则声明**类型 + 静态标签**；路径变量 `{site}` 自动映射成标签。
3. `level` 是**保留 key**：`raw / calibrated / derived`，受控取值。
4. 人工与 API 改标全部走**审计日志**；改规则可触发**历史回溯打标**任务。

**第二阶段 · 需要时 —— 数据集注册表（薄层，不动文件表）**
- 数据集 = 命名并固化的**标签组合（谓词）**，如
  `tokyo-pressure-raw ≔ type:pressure ∧ site:tokyo ∧ level:raw`。
- 其上挂：应到期望（对账）、`derived_from`（血缘）、负责人、SDK 订阅名。
- **文件表零改动** —— 数据集只是查询的「视图 + 元信息」。

> ✓ 每阶段独立交付、不返工；第一阶段即解决「类型爆炸」与元数据源头问题。
> ✓ 长尾数据永远可以只打标、不建数据集。
> ✓ 与现有 `file_types` 兼容。

## 治理决策（`6d`，设计已给推荐，待确认）

- **取值治理：key 严格受控，value 受控可扩。** 管理员定义 key 词表和每个 key 的合法取值；规则里只能选。
  路径变量提取出**未知值**时**不自动入库**，进「**待确认**」队列由管理员核准（防 `tokyo / Tokyo / TYO` 漂移）。
- **`file_types` 的角色：保留做粗分类。** 大类（`pressure / vibration / app_logs`，预计 10~20 个、稳定）；
  所有变种维度一律走标签。现有 glob 归类**降级为兜底**：规则声明的类型优先，glob 只兜没声明的旧数据。

## UI 界面（round 7 = 第一阶段的四屏，落在 Half A 之上）

- `7a` **规则表单新增「元数据」步骤**：声明类型 + 受控标签，路径变量自动映射（接入 `pages/Agents/RuleForm`）。
- `7b` **文件页标签组合筛选（faceted）**：左侧按 key 分组勾选，命中即拼谓词；预埋「另存为数据集」（`pages/Files`）。
- `7c` **设置 · 标签词表**：key 严格受控、取值受控可扩；`level` 系统保留不可删。删除取值不改动已打标文件，仅阻止
  后续采集再用（`pages/Settings` 新增 Tab）。
- `7d` **设置 · 待确认取值队列**：未登记值在此核准，操作 = 合并到既有值 / 核准为新值 / 拒绝（后台回溯改写）。

## 契约影响（拍板后落地的 on-ramp）

此能力**跨模块**，落地前须走契约流程（见 `CLAUDE.md`「契约文件」）：

- **DB 迁移**（只追加）：`tag_keys` 词表、`tag_values` 受控取值、`file_tags` 文件↔标签、
  `pending_tag_values` 待确认队列、标签变更审计；第二阶段 `datasets` 注册表。
- **proto**：采集规则需携带「声明类型 + 静态标签 + 路径变量→标签映射」——很可能改 `proto/v1/agent.proto`
  （只增字段），须在 `DECISIONS.md` 记录。
- **CP REST**（`/api/v1/...`）：词表 CRUD、文件按标签查询/筛选、待确认值核准/合并/拒绝、回溯打标任务。
- **文档**：`system-design.md` §3（数据模型）+ §5.9/§5.11（API）；`DECISIONS.md` 新决策条目。
- **SDK**（当前推后 T3-3/T4-4）：按标签/维度拉取是主要消费场景。
