## 3. 仪表盘（§7.3.1）——⚠️ 最大问题点

设计画了 4 张统计卡 + 7 日趋势图 + 在线状态列表 + 最近日志，页面也照做了。
**但 Control Plane 没有任何统计聚合端点（设计 §5.11 也从未定义）**，导致前端全部用近似值拼凑
（`Dashboard/index.tsx:96-130`）：

| 卡片 | 实际数据来源 | 问题 |
|------|-------------|------|
| 在线采集器 | listAgents(limit=100) 前端过滤 | >100 台时不准 |
| 今日上传 | **最近 20 条**上传日志里数今天的 | 上限 20，几乎必然错 |
| 总文件数 | listFiles(limit=1) 取 total | ✅ 勉强可用 |
| 存储用量 | **最近 20 条日志的 size 求和** | 与真实存储用量毫无关系；设计 §6.6 要求 madmin.BucketUsageInfo |
| 7 日趋势图 | 同样从 20 条日志推算 | 数据无意义 |

**定性**：这是"设计粗糙未覆盖实际需求"的典型样本——§7.3.1 只画了 UI 稿，
§5.11 REST 清单里没有对应的 `/api/v1/stats` 类端点，实现者只能硬凑。
需要补设计（Dashboard 统计 API）而不仅是修代码。
